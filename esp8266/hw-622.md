# HW-622 (ESP-12F, 1 relay) on ESPurna

A small relay board with an ESP-12F (4 MB flash), one relay and an optocoupler input. It has many screw terminals,
which makes it look like a 2-relay board; it has one relay.

![HW-622](https://raw.githubusercontent.com/blakadder/templates/master/assets/device_images/HW-622.webp)

*Photo: [Tasmota Device Templates](https://templates.blakadder.com/HW-622.html).*

## Image and pins

`esp8266-4m` (the board was installed with the 4 MB layout, its settings sit at the end of the 4 MB):

| Function | GPIO |
|----------|------|
| relay | 4 |
| opto input (button, `switch` mode) | 5 |
| LED (inverse) | 2 |

## The test board of `esp8266-4m`

This board is where the generic 4 MB image was made to work:

- **Boot loop** of the first generic image: garland's global palettes allocated 13 KB of heap before `setup()`; fixed by
  creating them on first use.
- **Memory.** With every driver the image had about 4 KB free and crashed during an update; it now carries relays,
  buttons, LEDs, RF, MCP23S08 and the sensor drivers only. lwIP 'Lower Memory' and no API handlers while the API is off
  brought the largest free block from 6-9 KB to 12-15 KB (MQTT and Home Assistant on); the WebUI loads whole and a
  browser upload of 825 KB completes in 30-45 s.
- **401 per chunk.** An upload that failed authentication built a new 401 response for every received chunk and ran the
  heap out (abort in `AsyncBasicResponse`, 2026-11-07); the answer is now built once per request.
- **Recovery without a wire**: in unstable mode ArduinoOTA still runs, over the board's own access point
  (`firmware_espota_net.py <bin> --host 192.168.4.1`); with too little heap for an OTA, `UNSTABLE` in the terminal reboots
  it into unstable mode with about 17 KB free.

## Tested

Relay, opto input, LED, MQTT, Home Assistant, web OTA, ArduinoOTA, the admin page. From ESPurna 1.15 (1CH inching
build) it kept its settings: that 1.15 kept the settings at the end of the real 4 MB chip, where the 4 MB layout finds
them.
